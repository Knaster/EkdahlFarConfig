The Ekdahl FAR Configuration software

This is the configuration software for the Knas Ekdahl FAR.

The software communicates with the instrument(s) via RS-232 over USB, all communications is based on the concept of commands as outlined in the general FAR documentation. The information here within will only cover the communications with the latest version of the Ekdahl FAR firmware as any updates or changes should not be done to any legacy compatibility code for older versions.

The basic concept of communication is that the configuration software will issue various information request commands ('rqi') and populate its various controls and status bars per the responses received. The rule of thumb is that each command issued generates a response, this can vary from a simple aknowledgement to returning a full set of data. The software is not to populate the GUI information whilst issuing commands but rather relies soley on responses in this regard.

In the initial phase of communication some information has to be fully received before requesting additional information. Certain commands will return an unknown number of responses thus those requests are generally followed by a 'nop'-command. When a 'nop' aknowledgement is received the software knows that the previous data has been exhausted.

The basic workflow for this software works as follows:

  • Issue a version request command to the FAR in order to know which command set to use
  • Issue a 'list'-command in order to receive the number of modules and commands contained within the instrument
  • Build a internal hierarchy from the responses of the 'list'-command using CommandSets.CommandSetModular.buildHierarchy
  • Issue a 'help'-command in order to build the help reference
  • Build the help using CommandSets.CommandSetModular.buildHelp
  • Build a plugin list from the internal module hierarchy using PluginHandler.buildPluginList
  • Request data for each module depending on their request data
  • Build a node map from the modules and command responses received. See the NodeHandler for more information
